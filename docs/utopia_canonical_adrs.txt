--------------------------------------------------------------------------------
1. СЕМАНТИКА БІТЕМПОРАЛЬНОГО ГРАФА НАМІРІВ (UTOPIA DB)
--------------------------------------------------------------------------------
Кожне архітектурне рішення в B-SDD є незмінним фактом у просторі двох часових осей:
1. Час дійсності / валідності (Valid Time, Tv): інтервал [valid_from, valid_to), що визначає, коли правило істинне в предметній області.
2. Час транзакції / запису (Transaction Time, Tt): інтервал [tx_from, tx_to), що фіксує, коли факт був фізично записаний у журнал бази даних.

Жоден запис не видаляється (WORM-архітектура). Заміщення застарілих інваріантів відбувається через створення нового вузла та закриття попереднього через ребро supersedes у таблиці intent_store.intent_supersessions.

2. КАТАЛОГ КАНОНІЧНИХ АКТИВНИХ ADR
--------------------------------------------------------------------------------

ADR-001: Bitemporal Intent Graph & Transaction Time Horizon
- Компонент: core
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Традиційні правила (CLAUDE.md, .cursorrules) плоскі, не мають історії, викликають галюцинації при модифікаціях. Векторні БД повертають суперечливі версії через семантичну схожість.
- Рішення: Збереження інваріантів як орієнтованого ациклічного графа (DAG) у бітемпоральній базі Utopia DB. Подвійна часова вісь Tv/Tt.
- Інваріант: Агент отримує лише правила, валідні в момент виконання: Tv <= NOW < Tv_end. Минулі стани відтворюються точно на будь-яку історичну мітку Tv_snap.

ADR-002: Deterministic Pre-Flight Compilation & Sub-500 Word Budget
- Компонент: core
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Роздутий контекст деградує якість генерації коду LLM.
- Рішення: Детермінований компілятор active_rules.md на базі чистої стандартної бібліотеки Python (0 сторонніх залежностей). Обчислення MD5-хешів, фільтрація активних інваріантів.
- Інваріанти:
  * Час компіляції: строго < 50 мілісекунд.
  * Бюджет слів: строго < 500 слів.
  * Нуль сторонніх бібліотек у src/core/.

ADR-003: Procedural Skill Lifecycle & The Rule of 2 Self-Authoring
- Компонент: skills
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Інваріанти вказують обмеження, але не процедуру дій для складних задач.
- Рішення: Трьохфазний життєвий цикл процедурних навичок. Навичка створюється автономно лише після того, як операція успішно повторилася щонайменше у двох незалежних сесіях (Rule of 2).

ADR-004: AST Impact Graph Routing & Selective Test Dispatch
- Компонент: scrapers / core
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Запуск усього набору тестів на кожен коміт паралізує швидкість розробки.
- Рішення: Синтаксичний аналіз AST через GitNexus. Побудова точного графа викликів і залежностей, обчислення топологічного радіуса ураження змін. Запуск тільки афектованих тестів.

ADR-005: Automated Architectural Fitness Gates & Boundary Auditing
- Компонент: scrapers / core
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Архітектурні порушення та циклічні імпорти помічаються надто пізно.
- Рішення: Фаза перевірки фітнес-функцій: 100% проходження тестів радіуса ураження, перевірка імпортів через AST-візитор на відповідність шарам чистої архітектури.

ADR-006: Multi-Harness Session Distillation & Context Compaction
- Компонент: candidate / memory
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Довгі діалоги накопичують шуми, знижуючи швидкість та якість відповідей моделі.
- Рішення: SessionDistiller виконує стиснення сесійного журналу: відсікання помилкових спроб, вилучення ключових артефактів, передача стислого звіту (<4000 токенів) у довгострокову пам'ять AI Memory.

ADR-007: Multi-Session Sprint Chaining & Autonomous Handoff Protocol
- Компонент: core
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Складні фічі не вміщуються в одне контекстне вікно без ризику деградації.
- Рішення: Ланцюжки спринтів. Кожен спринт завершується валідацією sprint_handoff.json та генерацією run_sprint_XXX.sh.
- Інваріант: Кількість порушених інваріантів має не зростати: Delta C = C_{t+1} - C_t <= 0.

ADR-008: DRAKON Visual Logic Standard & Developer Workbench
- Компонент: drakon / ui
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Складні розгалужені алгоритми у тексті важкі для сприйняття людиною-оператором (HITL).
- Рішення: Стандарт ДРАКОН: головний маршрут (Happy Path) завжди вертикальний (шампур), гілки помилок відходять праворуч, жодних перетинів ліній.
- Інваріанти: C = 0 (перетини ліній заборонені), X = 0 (строга вертикальна вісь).

ADR-009: Astryx Design System & Universal Cockpit Architecture
- Компонент: ui / cockpit
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Візуальний шум веб-інтерфейсів та незручна навігація дезорієнтують оператора.
- Рішення: Швейцарська інженерна ергономіка: фіксована висота 100vh без прокручування body (no-body-scroll), ізольовані робочі зони (AstryxZoneBoundary), палітра Slate, висока щільність даних.

ADR-010: Universal Multi-Project & Standard Algorithm Catalog
- Компонент: bots / catalog
- Статус: accepted (valid_to = infinity, tx_to = infinity)
- Проблема: Необхідність перемикання між різними інструментами для суміжних репозиторіїв.
- Рішення: Інтеграція єдиного селектора проектів та каталогу валідованих планарних алгоритмів ДРАКОН (черги, ретраї, валідації).

ADR-011: Live GitHub API Sync & Appwrite Realtime Phase Sync
- Компонент: sync / realtime
- Статус: accepted (valid_to = infinity, tx_to = infinity)

- Рішення: Двостороння синхронізація через Server-Sent Events (SSE) та Appwrite Realtime. Підписання фазових переходів людиною через WebCrypto API (Ed25519).

ADR-012: Production Deployment & Telemetry Instrumentation

ADR-013: Utopia DB Bitemporal DAG View & Headless Pi Isolation Engine

ADR-018: Realtime Sovereign Mesh, Cluster Discovery & Distributed Leases

ADR-019: Autonomous Multi-Agent Consensus & Quorum Arbitration

- Рішення: Двофазний консенсус ConsensusEngine: вимога досягнення N >= 2/3 голосів агентів кластера, криптографічні бюлетені голосування в незмінному реєстрі.

ADR-020: Sovereign Agent Self-Correction & Automated Rollback Compensation

ADR-FE-001: Frontend Cockpit Architecture & Fault-Tolerant Boundary
