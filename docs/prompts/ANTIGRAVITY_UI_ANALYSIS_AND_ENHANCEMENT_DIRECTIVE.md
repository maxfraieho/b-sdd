2. **Gemini Spark (Головний Архітектор)**:

3. **Antigravity (Ти — Програміст & Дизайнер)**:

## 2. ІНСТРУМЕНТАЛЬНИЙ АРСЕНАЛ СЕСІЇ

Під час роботи обов'язково використовуй інтегровані канали:
1. **MCP `bsdd` (Локальний шлюз :8765)**:
   - `astryx_canvas_push` / `astryx_canvas_get`: синхронізація ДРАКОН-схем із живим канвасом верстака.
   - `astryx_deploy_trigger`: тригер production-деплою на Cloudflare Pages з автоматичним запуском `deploy_cloudflare_pages.sh`.
   - `drakon_planar_validate`, `drakon_svg_export`, `drakon_code_compile`: генерація та верифікація візуальних графів ($C=0$, $X=0.0$).
   - `utopia_check_invariants`: перевірка бюджету активних правил (<500 слів за ADR-005) та стану ADR.
2. **MCP `notebooklm` (Міст до Архітектора)**:
   - Блокнот SSoT `205ee2ec-e0d2-4ba6-badf-44f2de02c7e2`: запити щодо рішень Spark'а, структури дашбордів, актуального стану спринтів та контрактів даних.
3. **Контур тестування на ноутбуці `.30` (`vokov@192.168.3.30`)**:
   - Віддалений запуск браузера через SSH (`powershell.exe`).
   - Зняття скріншотів сторінки у реальному Chromium-рушії через headless-режим або CDP-автоматизацію.
   - Підготовка інтерактивного середовища для ручного перегляду Керівником проєкту.

## 3. ЧОТИРИФАЗНИЙ ПРОТОКОЛ АНАЛІЗУ ТА ДООПРАЦЮВАННЯ ІНТЕРФЕЙСУ

### ФАЗА 1: АРХІТЕКТУРНИЙ ТА СЕНСОРНИЙ АУДИТ (SSoT + UTOPIA + ASTRYX)
1. **Синхронізація з Архітектором Spark**:
   - Зроби запит через `notebooklm` до блокнота `205ee2ec-e0d2-4ba6-badf-44f2de02c7e2`: отримати актуальні архітектурні вимоги до Astryx Cockpit UI (ADR-008, ADR-009, ADR-011, ADR-013).
   - Зафіксуй очікувані сутності: `PhaseStepper`, `DrakonStudio`, `BitemporalRadar`, `TasksPanel`, `TelemetryDrawer`, `InvariantDrawer`.
2. **Аудит інваріантів Utopia DB (.251)**:
   - Виклич `utopia_check_invariants` через MCP `bsdd`. Переконайся у валідності активних правил (<500 слів).
   - Перевір доступність ендпоінтів телеметрії супервайзера (`http://192.168.3.161:8161/health`) та Laya System 1 (`http://192.168.3.251:9623/health`).
3. **Аналіз поточної кодової бази UI**:
   - Переглянь `~/projects/b-sdd/b-sdd-ui/src/App.tsx` та ключові компоненти.
   - Звір поточний стан зі специфікацією: вияви захардкоджені моки, які потребують заміни на реальні SSE-стріми (`useTelemetryRealtime`, `usePhaseRealtime`).

### ФАЗА 2: АВТОМАТИЗОВАНИЙ АУДИТ ТА ПЕРЕВІРКА ВІДСУТНОСТІ РЕГРЕСІЙ
1. **Перевірка компіляції та типів**:
   - Запусти у `~/projects/b-sdd/b-sdd-ui`: `npm run build` (або `tsc -b && vite build`).
   - Усунь будь-які помилки типізації TypeScript (`strict: true`).
2. **Аудит доступності, контрасту та структури (a11y)**:
   - Перевір колірну палітру теми (Slate/Zinc/Amber/Emerald) на відповідність WCAG AA (контраст тексту до фону не менше 4.5:1).
   - Переконайся у коректній роботі перемикача теми Dark/Light без артефактів інверсії.
3. **Аудит стабільності ДРАКОН-полотна**:
   - Перевір компонент `DrakonStudio`: валідація схеми через `drakon_planar_validate`, відсутність перетинів зв'язків ($C=0$), коректне масштабування та панорамування (Pan & Zoom).

### ФАЗА 3: ВІЗУАЛЬНИЙ АУДИТ НА НОУТБУЦІ `.30` (АВТОМАТИЧНИЙ ТА РУЧНИЙ)
1. **Автоматична перевірка через браузер на `.30`**:
   - Запусти на ноутбуці `.30` через SSH Chrome/Edge у headless-режимі для захоплення скріншотів `https://b-sdd-ui.pages.dev/`:
     ```powershell
     & "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless --screenshot="C:\Users\vokov\AppData\Local\Temp\b_sdd_ui_full.png" --window-size=1920,1080 "https://b-sdd-ui.pages.dev/"
     ```
   - Скопіюй скріншот на хост `.161` через scp/ssh та проаналізуй завантаження шрифтів, сітку макета та відсутність горизонтального скролу.
2. **Ручний аудит Керівником проєкту (HITL Human-in-the-Loop)**:
   - Надішли Керівнику чіткий структурований чек-лист для перегляду у звичайному вікні браузера на `.30`:
     * Ергономіка кнопок головних дій (залишати великими, доступними, не ховати в dropdown/kebab-меню).
     * Зчитуваність стану кластера у шапці (`Topbar`): зелений/жовтий/червоний індикатори хостів `.161`, `.184`, `.251`.
     * Поведінка модальних вікон (`AdrReaderModal`, `ReviewGateModal`) на екрані ноутбука.
     * Мобільний режим адаптивності (`useIsMobile`) при звуженні вікна.

### ФАЗА 4: ІТЕРАТИВНЕ ДООПРАЦЮВАННЯ, ЗБІРКА ТА ДЕПЛОЙ
1. **Точковий рефакторинг та покращення UX**:
   - Доопрацюй мікроінтеракції за принципами скіла `make-interfaces-feel-better`: плавні переходи (150–200ms), скелетони під час завантаження телеметрії, тактильні ховери.
   - Забезпеч деградований режим (Degraded Mode Banner): якщо бекенд супервайзера або Utopia тимчасово недоступні, UI не повинен «падати», а має відображати попередження та кешовані дані.
2. **Локальна валідація та синхронізація**:
   - Виконай синхронізацію оновленого канвасу через `astryx_canvas_push`.
   - Запусти повний білд `npm run build`.
3. **Публікація в Cloudflare Pages**:
   - Виклич інструмент MCP `astryx_deploy_trigger(environment="production")`.
   - Дочекайся завершення збірки та перевір HTTP 200 на `https://b-sdd-ui.pages.dev/`.
4. **Фіксація в WORM-леджері та звіт для Spark**:
   - Сформуй підсумковий машинозчитуваний звіт оновлення інтерфейсу `INBOX_GEMINI_SPRINT_XXX_UI_REVAMP_REPORT`.
   - Зафіксуй WORM-запис в Utopia DB (.251) через `utopia_worm_append`.
