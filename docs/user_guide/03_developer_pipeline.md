# Розділ 3. Пайплайн розробника: CLI, ДРАКОН-моделювання та TDD

## 3.1 Основні команди CLI B-SDD

B-SDD містить уніфікований інтерфейс командного рядка на базі Python standard library (`src/cli/main.py`), а також готові оболонкові скрипти.

### 1. Запуск інтерактивного Workbench
```bash
./run_workbench.sh
```
- Піднімає бекенд на порту `8765` (`src/server/workbench_server.py`).
- Піднімає Vite інтерактивний Workbench на `http://localhost:5173`.
- Автоматично звільняє зайняті порти перед запуском.

### 2. Запуск передпольотного компілятора правил
```bash
python3 -m src.cli.main compile
```
- Сканує репозиторій, виявляє активні ADR та інваріанти.
- Генерує знімок `.context/active_rules.md` із часом $<50$ мс і розміром $\le 500$ слів.
- Якщо передати аргумент `--files file1.py file2.ts`, компілятор сфокусується на відповідних архітектурних доменах.

### 3. Валідація ДРАКОН-алгоритмів
```bash
python3 -m src.cli.main drakon validate specs/008-sovereign-copilot-and-gateway/logic.drakon.json
```
- Перевіряє планарність графа, відсутність перетинів $C=0$, наявність заголовка, коректність переходів.

### 4. Генерація коду за схемою ДРАКОН
```bash
python3 -m src.cli.main drakon parse path/to/scheme.drakon.json
```
- Експортує логіку схеми у структуроване синтаксичне дерево (IR) або скелет функції на Python.

### 5. Синхронізація сесії та генерація Handoff
```bash
# Дистиляція поточної сесії:
python3 -m src.cli.main distill

# Створення контракту передачі наступному агенту:
python3 -m src.cli.main handoff --prompt "Опис задачі наступного спринту"
```

## 3.2 Пайплайн створення нового архітектурного рішення (ADR)

1. **Створення файлу:** Створіть файл у `docs/adr/ADR-XXX-назва.md` за форматом MADR 3.0:
   ```markdown
   # ADR-013: Назва архітектурного рішення

   - **Status:** proposed | accepted | superseded by ADR-YYY
   - **Valid-Time:** [2026-09-17, infinity)
   - **Transaction-Time:** [2026-09-17, infinity)
   - **Component:** core | server | ui | drakon | adapters
   - **Severity:** normal | critical

   ## Context & Problem Statement
   Чіткий опис проблеми, контексту та обмежень.

   ## Invariants
   1. **ADR-013-INV-01:** Формальне твердження обов'язкового правила.

   ## Decision Outcome
   Обране рішення, наслідки та компроміси.
   ```
2. **Верифікація компілятором:** Запустіть `python3 -m src.cli.main compile` — нове рішення автоматично додасться до інваріантів системи.
3. **Супресія (Заміна):** Якщо нове рішення замінює старе (наприклад, ADR-013 замінює ADR-003), у шапці нового вказується `supersedes: [ADR-003]`, а в старому встановлюється `Status: superseded` та $V_{end} = NOW$. Старе рішення більше ніколи не потрапить у контекст агента.

## 3.3 Правило двох (The Rule of 2) для автономних навичок

Коли ви помічаєте, що інженерна послідовність дій (наприклад, деплой на Cloudflare Pages, генерація звіту для Kindle, індексація графа коду) повторюється $\ge 2$ разів:
1. Запустіть створення навички агента:
   ```bash
   python3 -m src.cli.main skill create --name "my-workflow-skill"
   ```
2. Навичка зберігається в `.agents/skills/<name>/SKILL.md` і стає першокласним інструментом, доступним для автономного виконання будь-яким ШІ-агентом.
