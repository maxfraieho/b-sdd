# Розділ 6. Децентралізований консенсус агентів та 2/3 кворум голосування

## 6.1 Чому автономним агентам потрібен консенсус?

У складних інженерних екосистемах паралельно діють агенти з різними спеціалізаціями: Агент-Архітектор, Агент-Рефакторер, Агент-Верифікатор і Агент Документації. Коли один з агентів пропонує суттєву мутацію коду (наприклад, зміну структури бази даних або заміну ADR), одноосібне рішення може призвести до непоправних збоїв.

У Спринті 019 впроваджено децентралізований рушій консенсусу `ConsensusEngine` (`src/adapters/consensus_engine.py`), що реалізує візантійсько-стійкий арбітраж голосування.

---

## 6.2 Математична модель кворуму більшості ($N \ge 2/3$)

Для прийняття будь-якої архітектурної пропозиції потрібне досягнення суворого кворуму кваліфікованої більшості:

$$\text{Quorum} \iff \frac{\text{Голоси «ЗА»}}{\text{Загальна кількість голосів}} \ge \frac{2}{3} \quad \land \quad \text{Голоси} \ge \text{MinVoters}$$

### Життєвий цикл пропозиції:
1. **`voting` (Голосування):** Пропозиція відкрита для прийняття голосів агентів протягом встановленого TTL (наприклад, 60–300 с).
2. **`accepted` (Схвалено):** Набрано $\ge 2/3$ голосів схвалення. Пропозиція негайно стає обов'язковою для застосування.
3. **`rejected` (Відхилено):** Поріг вето або кількість голосів «ПРОТИ» унеможливлює досягнення $2/3$.
4. **`expired` (Прострочено):** Час голосування вичерпано без набору необхідного кворуму.

## 6.3 Бітемпоральний леджер бюлетенів

Кожен голос, відданий агентом, записується як незмінний криптографічний бюлетень:
```json
{
  "proposal_id": "prop_1789758696_3b3e12",
  "voter_id": "agent-alpha",
  "vote": "approve",
  "signature": "sig-ed25519-hex",
  "rationale": "Refactoring meets ADR-002 pure runtime invariants",
  "t_x": "2026-09-18T19:11:38.770511+00:00"
}
```

Усі бюлетені синхронізуються із базою знань Utopia DB (:9922). Жоден агент не може відкликати чи підробити свій голос заднім числом.

## 6.4 Операторський контроль у Astryx Cockpit

1. **System Pulse Telemetry:** У випадаючому вікні пульсу системи оператор бачить поточний рядок `Agent Quorum (2/3 Majority)` зі статусом `Consensus Ready`.
2. **Copilot Quick Pill:** Кнопка-підказка `Кворум (2/3 Консенсус)` у Copilot Stream дозволяє оператору в один клік отримати звіт про всі відкриті голосування та позицію кожного агента.
