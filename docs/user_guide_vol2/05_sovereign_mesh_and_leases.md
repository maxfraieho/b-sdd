# Розділ 5. Суверенна мережа вузлів, кластерна синхронізація та розподілені лізи

## 5.1 Топологія суверенного кластера B-SDD

Суверенна архітектура B-SDD розгортається на фізично та логічно розподіленій мережі апаратних вузлів із чітким розподілом ролей:

1. **Вузол `.161` (Orchestration & Dev Plane):** Робоче середовище інженера-оператора, первинний компілятор правил, середовище розробки та шлюз інструментів.
2. **Вузол `.184` (Inference & Background Runner):** Високопродуктивний сервер виконання інференсу LLM (порт `:18880`), сервер статичного аналізу AST GitNexus (порт `:4747`), сервер верстата `workbench_server` (порт `:8765`), та автономний конвеєр доставки Kindle (`send-to-kindle`).
3. **Вузол `.251` (Utopia DB Bitemporal Plane):** Захищений сервер бітемпоральної бази знань та незмінного леджера (порт `:9922`). Усі транзакції $T_x$ та інтервали дійсності $T_v$ фіксуються тут.

## 5.2 Децентралізоване виявлення вузлів без зовнішніх брокерів (ADR-002)

На відміну від важких хмарних систем (типу Consul, Zookeeper чи etcd), кластерний менеджер `ClusterNodeRegistry` реалізований на 100% чистій стандартній бібліотеці Python 3 (`src/adapters/cluster_sync.py`):
- **Хартбіт-моніторинг:** Періодичний огляд здоров'я та відгуку вузлів (затримка $\le 2$ мс).
- **TTL вузлів:** Якщо вузол не оновлює стан протягом 30 секунд, він позначається як тимчасово недоступний без зупинки всього кластера.
- **Офлайн-паритет:** Якщо зв'язок між вузлами переривається, локальний верстат на кожному вузлі продовжує повнофункціональну роботу з локальними кешами.

## 5.3 Розподілені бітемпоральні лізи (Distributed Leases)

Коли кілька автономних агентів одночасно виконують задачі (наприклад, оптимізацію AST або оновлення документації), виникає ризик колізій та одночасного перезапису файлів.

Для захисту кодової бази впроваджено механізм розподілених ліз (`ClusterLeaseManager`):
- **Захоплення лізи (`POST /api/cluster/lease/acquire`):** Агент запитує ексклюзивний доступ до ресурсу (наприклад, `specs/018-cluster-sync`). Ліза видається на фіксований TTL (за замовчуванням 60 секунд) із прив'язкою до ідентифікатора агента та вузла.
- **Бітемпоральна фіксація:** Захоплення реєструється із транзакційним часом $T_x$ та інтервалом чинності $T_v$.
- **Автоматичне звільнення:** Після завершення фази агент викликає `POST /api/cluster/lease/release`. Якщо агент завис або впав, ліза автоматично втрачає чинність після вичерпання TTL, унеможливлюючи вічні блокування (*deadlocks*).
