# Розділ 3. Візуальні алгоритми ДРАКОН: Чому планарність рятує ШІ від галюцинацій

## 3.1 Походження та філософія мови ДРАКОН

Мова **ДРАКОН** (*Дружелюбный Русский Автоматический Код, Облегчающий Наглядность*) була розроблена в межах космічної програми багаторазового корабля «Буран» для усунення помилок людського фактора в критичних бортових системах. У системі B-SDD ДРАКОН отримав друге народження як універсальна математична мова взаєморозуміння між Людиною та Суверенними ШІ-Агентами.

Сучасні великі мовні моделі (LLM) часто помиляються при читанні довгих спагеті-умов (`if-else-switch`) у текстовому коді через розмивання механізму уваги (*attention dilution*). Формальна топологія ДРАКОН усуває цю проблему, перетворюючи логіку на детермінований орієнтований граф без перетинів.

## 3.2 Фундаментальні геометричні інваріанти (ADR-008)

Кожна схема ДРАКОН у B-SDD (`logic.drakon.json`) підлягає автоматичній валідації через `DrakonValidator` за такими суворими правилами:

### 1. Планарність графа: нуль перетинів ($C = 0$)
У схемі категорично заборонені будь-які перетини ліній зв'язку ($C = 0$). Перетин ліній створює просторову двозначність для ШІ-агента та візуальний шум для оператора. Якщо алгоритм неможливо намалювати без перетинів, це означає, що функція перевантажена і потребує декомпозиції на кілька підойнігтів (deep modules).

### 2. Вертикальний шампур (Happy Path, $X = 0$)
Головний, найімовірніший та успішний сценарій виконання завжди спрямований строго зверху вниз уздовж центральної вертикальної осі ($X = 0.0$). Оператор або агент, поглянувши на шампур, за 2 секунди бачить суть алгоритму без читання розгалужень.

### 3. Правило правого крила ($X > 0$)
Будь-які запитання (`question`), винятки, альтернативні сценарії та обробка збоїв відгалужуються **строго праворуч** від головного шампура:
- Маршрут «ТАК / YES»: продовжує рух вниз по головному шампуру.
- Маршрут «НІ / NO»: виходить праворуч і повертається в магістраль або веде до контрольованого терміналу.

### 4. Термінальна чіткість: один вхід — один вихід
Кожна схема починається з вузла `headline` та завершується єдиним вузлом `end`. Алгоритми без ясного фінішу заборонені на рівні компілятора.

## 3.3 Семантична прив'язка до архітектурних інваріантів (Semantic Bindings)

У B-SDD кожен вузол схеми ДРАКОН має поле `semantic_binding`:
```json
{
  "node_id": "cond_quorum_reached",
  "node_type": "question",
  "label": "Отримано схвальний кворум більшості (N >= 2/3 голосів)?",
  "edges": { "down": "step_apply_consensus", "right": "step_reject" },
  "semantic_binding": {
    "adr_invariant_id": "ADR-005",
    "severity": "critical"
  },
  "x": 0.0,
  "y": 6.0
}
```

Це пов'язує графічний блок із канонічним правилом у базі знань. Якщо інженер чи агент намагається змінити алгоритм у спосіб, що суперечить `ADR-005`, передпольотний компілятор B-SDD миттєво генерує помилку несумісності до початку генерації коду.

## 3.4 Базові примітиви палітри ДРАКОН

1. **Заголовок (Headline):** Точка входу в алгоритм, назва контексту та ініціалізація змінних.
2. **Дія (Action):** Атомарна інструкція, мутація стану або виклик чистої функції.
3. **Питання (Question):** Логічне розгалуження з двома виходами (Вниз — позитивний, Праворуч — альтернативний).
4. **Кінець (End):** Фіксація успішного або термінального завершення гілки.
5. **Вставка (Insertion):** Посилання на вкладену схему або дочірній агентський процес.
