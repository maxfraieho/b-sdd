# Genspark Prompt: B-SDD Human-in-the-Loop Operator Workbench
## Суверенний веб-інтерфейс оператора та візуальний кокпіт агентної розробки (SaaS Edition)

---

## 1. ВСТУП ТА ПРОДУКТОВЕ ПОЗИЦІОНУВАННЯ

**Назва продукту:** B-SDD Operator Workbench (Cockpit)  
**Цільове призначення:** Професійне робоче місце інженера/архітектора (Human-in-the-Loop) для керування поетапними циклами розробки AI-агентів, візуального проектування алгоритмів на мові ДРАКОН, контролю бітемпоральних архітектурних рішень (ADR) та автоматизованого запуску мультисесійних спринтів (B-SDD Dynamic Handoff).  
**Бізнес-модель:** Multi-Tenant B2B SaaS на базі Appwrite BaaS (Auth, Projects, Teams, Usage Analytics, Subscriptions) з можливістю локального суверенного запуску (On-Premises).  
**Платформа розгортання:** Cloudflare Pages (React 18/19 + TypeScript + Vite + Tailwind CSS + Lucide Icons + shadcn/ui).

---

## 2. КЛЮЧОВА КОРИСТУВАЦЬКА ЛОГІКА (HUMAN-IN-THE-LOOP DEV CYCLE)

Система реалізує не «сліпу» генерацію коду, а керований оператором поетапний цикл із контролем якості на кожному кроці:

```
[ Етап 1: Ініціація циклу ] ──> Вибір проекту та сценарію (Refactoring / New Feature / Bugfix)
              │
              ▼
[ Етап 2: Архітектурний контракт ] ──> ADR (Чому) + ДРАКОН-схема (Як / Алгоритм)
              │
              ▼
[ Етап 3: Pre-Flight Gate ] ──> Компіляція правил (.context/active_rules.md <20 мс, <500 слів)
              │
              ▼
[ Етап 4: Поетапне виконання ] ──> Агент пише код строго в межах поточного кроку
              │
              ▼
[ Етап 5: Автоматичні тести ] ──> Pytest / AST Fitness Gates / Linting
              │
              ▼
[ Етап 6: ШЛЮЗ ЛЮДИНИ (HITL Gate) ] ◄── ОПЕРАТОР ПЕРЕГЛЯДАЄ РЕЗУЛЬТАТ:
              │                     • [ Затвердити та перейти далі ]
              │                     • [ Скоригувати ДРАКОН-схему / код ]
              │                     • [ Перезапустити крок з новим промтом ]
              ▼
[ Етап 7: Дистиляція та Handoff ] ──> main.py distill + sprint_handoff.json + генерація команди наступного спринту
```

### 4.3 ЕКРАН 1: Спринт-Кокпіт (Dev Cycle Command Center — ГОЛОВНИЙ ЕКРАН)
Центральний простір розділено на 3 логічні зони:

1. **Верхня картка сценарію (Scenario Header):**
   - Перемикач режиму: `[ 🔄 Рефакторинг існуючого коду ]` | `[ ✨ Розробка нової фічі ]` | `[ 🐛 Виправлення дефекту ]`.
   - Загальний прогрес циклу (наприклад, `Етап 4 з 7 — 57%`).
   - Кнопки керування: `[ 🔁 Перезапустити цикл ]`, `[ ⏸️ Призупинити ]`.

2. **Поетапний степпер життєвого циклу (Phased HITL Stepper):**
   Кожен крок відображається у вигляді картки зі статусом:
   - **Крок 1: Формулювання наміру (ADR & Spec)** — `[ COMPLETED ]` (Посилання на ADR-024).
   - **Крок 2: Алгоритмічна схема ДРАКОН** — `[ COMPLETED ]` (Схема `sovereign_routing.drn`).
   - **Крок 3: Pre-Flight компіляція правил** — `[ COMPLETED ]` (433 слова, 18 мс, 0 застарілих правил).
   - **Крок 4: Виконання у коді (Code Execution)** — `[ IN PROGRESS ]` (Модуль `src/adapters/llm_gateway.py`).
   - **Крок 5: Автоматичні тести (Fitness Gates)** — `[ PENDING ]` (Очікує запуску `pytest`).
   - **Крок 6: ШЛЮЗ ПЕРЕВІРКИ ЛЮДИНОЮ (Human Review Gate)** — `[ BLOCKED / AWAITING HUMAN ]`:
     - Інтерактивна плашка дій для оператора:
       - `[ ✅ Затвердити результат та перейти до Handoff ]`
       - `[ ✏️ Скоригувати код / схему у редакторі ]`
       - `[ 🔁 Повторити етап з уточненням ]`
   - **Крок 7: Дистиляція та Dynamic Handoff** — `[ PENDING ]` (Генерація команди наступного спринту).

3. **Нижня панель: Консоль естафети (Sprint Handoff Console):**
   - Вікно попереднього перегляду `.context/next_sprint.md`.
   - Готовий блок термінальної команди для наступної сесії:
     `./run_b_sdd.sh "Виконати Milestone 2: Реєстр інструментів..."`
   - Кнопка в один клік: `[ 📋 Скопіювати команду запуску ]` та `[ 🚀 Авто-диспатч агента ]`.

### 4.4 ЕКРАН 2: Радар ADR (Bitemporal Knowledge Graph Viewer)
- **Часовий слайдер (Valid Time Slider):** Можливість перетягувати дату від початку проекту до сьогодні та спостерігати, які рішення ставали чинними, а які заміщувалися.
- **Фільтр статусів:** `Всі`, `Accepted (Діючі)`, `Superseded (Заміщені)`, `Proposed`, `Deprecated`.
- **Двоколонковий вигляд:**
  - Ліворуч: список або таймлайн карток ADR із зазначенням зв'язків заміщення (`Замінює ADR-008`, `Замінено на ADR-013`).
  - Праворуч: повний переглядач тексту обраного ADR у Markdown із підсвічуванням інваріантів та списком зачеплених компонентів коду.
